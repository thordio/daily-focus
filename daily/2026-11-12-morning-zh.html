谷歌推出了基于新模型 Gemini Decision 1 的 Gemini Decisions API。该 API 可以在一次处理中评估最多 1,000 个是/否、选择题和评分标准问题，支持文本、图像、音频、视频和 PDF 输入。它支持最多 255 个选项的选择题，并返回结构化答案，例如真/假或所选选项。该服务可通过 Google AI Studio 使用。
💡 为什么重要： 该 API 为开发者提供了一个专用端点，用于大规模结构化决策任务，而不必依赖通用聊天模型。对音频、视频和 PDF 的多模态支持，使文档分拣、合规检查和呼叫中心决策流程的自动化成为可能。不过，早期对比显示 Jev 在纯文本用例上仍然更快、更便宜，因此成本和延迟是采用的关键因素。
📊 关键数据: 1,000
背景知识
决策 API 是专用端点，返回结构化结论（如真/假或所选选项）而非自由文本，适合自动审核、合规和分拣等任务。与通用聊天机器人不同，它们可能返回校准概率，但近期研究对向 LLM 询问置信度的可靠性提出了质疑。Jev 是较早的决策 API，以快速、低成本的纯文本决策著称；Gemini Decisions 增加了音频、视频和 PDF 支持，这是第一代决策 API 无法处理的。
关键细节

💡 为什么重要： 该禁令凸显了AI代理普及与航空公司反机器人措施之间的摩擦，影响寻求自动化的旅客和开发旅行代理的开发者。它表明航空公司可能抵制第三方自动化，迫使用户转向手动预订或官方API/旅行社。这可能减缓AI代理在价格敏感、高风险市场中的部署。

苹果提出学习式检索方法，加速RAG系统

hackernews zerop · 2026-11-11 · ⌛ 2 分钟阅读
评分依据：Apple's research on faster retrieval for RAG addresses a practical bottleneck for production AI systems. The HN discussion adds value with practitioner skepticism and comparisons to Spotify's Parallel Fusion Router, indicating relevance for hyperscale deployments, though not a paradigm shift.
📰 发生了什么
苹果公司提出了一种学习式检索方法，旨在提高检索增强生成（RAG）系统的速度与效率。该方法属于学习式检索范式，与此前 Spotify 的 Parallel Fusion Router 类似；后者利用教师 LLM 训练较小的路由 LLM，并以 LLM-as-judge 奖励函数进行优化。这类方法主要适用于处理数亿文档的超大规模部署。
💡 为什么重要： 更快的检索直接解决生产环境 AI 系统的关键瓶颈——检索延迟直接影响成本与用户体验。超大规模部署处理大量文档，能从学习式检索中获益最多。但检索与生成质量之间存在权衡；学习式检索可能因启发式选择的上下文而引入偏差，影响最终输出质量。
背景知识
检索增强生成（RAG）让大语言模型从外部知识库获取信息，但检索步骤可能成为延迟瓶颈。传统方法依赖 embedding 模型或词法搜索，可能无法充分捕捉语义细微差别。学习式检索训练模型自行决定检索动作，有望同时提升速度与相关性。
关键细节
学习式检索通常采用教师-学生训练模式；Spotify 的 Parallel Fusion Router 用教师 LLM 训练小型路由 LLM，并使用 LLM-as-judge 的奖励函数。与传统的 embedding 相似度或关键词匹配（如 grep）不同，这类方法可学习选择更相关的上下文，同时降低检索开销。
