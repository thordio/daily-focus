恶意 struct.py 攻破 Claude Code Opus 5 自动模式

hackernews Recursing · 2026-08-31 · ⌛ 2 分钟阅读
评分依据：High-value security research detailing a novel attack vector against Claude Code's auto mode, exploiting Python module shadowing; comments provide substantive debate on classification and implications, enhancing value.
📰 发生了什么
安全研究机构 Embrace The Red 演示通过一个简单的网页摘要请求攻破 Claude Code Opus 5 的 Auto Mode，成功执行任意代码，实验室成功率为 60-80%。攻击者让代理处理网页时，代理会编写并运行一个 Python 解码脚本；攻击者在解压目录中植入恶意 struct.py，当脚本运行时该文件遮蔽 Python 标准库模块，从而执行攻击者代码。该攻击不需要劫持代理意图，仅依赖代理的固定工具使用行为。
💡 为什么重要： 这表明自主编码代理不仅面临提示注入风险，还可能因文件解析和模块导入机制被间接利用，达到任意代码执行。企业若依赖 Claude Code 等自主代理处理外部内容，需加强沙箱、文件系统隔离和工具白名单，否则攻击者可能通过恶意网页实现持久化入侵。
📊 关键数据: -80%
背景知识
Claude Code 是 Anthropic 的编码代理，Auto Mode 可自主执行多步任务。提示注入指通过网页等外部内容向模型输入恶意指令；Python 模块遮蔽指当前目录中存在与标准库同名的 .py 文件时，解释器会优先加载该文件。
关键细节
攻击依赖 Python 模块遮蔽：恶意 struct.py 放在攻击者控制的解压目录中，脚本从该目录运行时优先导入恶意模块而非标准库 struct。攻击利用 Claude Code 在自动模式下会编写解码脚本并用 python -c 执行的可预测行为，不需要改变代理的任务目标即可实现代码执行。

LongGuard 揭示长上下文安全护栏失效机制并提出无训练缓解方法

rss ArXiv cs.AI · 2026-08-31 · ⌛ 2 分钟阅读
评分依据：High-value technical research: systematically demonstrates that mainstream safety guardrails fail significantly on long contexts (unsafe recall drops >50%), provides mechanistic analysis (attention dilution, logit margin compression), and offers a training-free mitigation. Important for AI safety practitioners and model deployment; no discussion data available.
📰 发生了什么
LongGuard 框架在 0.25k 至 32k 长度的 SafetyNIAH 网格上评估了 15 种主流安全护栏，发现不安全样本召回率平均单调下降超过 50%。通过 Benign-Fill 与 Needle-Repeat 配对实验，失效被归因于不安全“针”的比例稀释，而非绝对长度。对 6 个护栏的三层分析定位了机制：注意力质量被稀释、不安全对安全 logit 差距同步压缩、检测决策随之崩溃。基于此提出两种无训练缓解方法 CAHR-CD 和 CAHR-AHS，在五个基准上分别将六护栏平均提升 22% 和 13%。
💡 为什么重要： 安全护栏是大模型防御有害输入输出的最后防线，其在长上下文场景下大幅失效意味着长文档分析、长对话和推理模型输出可能绕过安全检测。无训练缓解方法使现有部署无需重新训练即可提升长上下文安全性，对 AI 安全从业者和生产环境部署具有直接价值。
📊 关键数据: 50% 22% 13%
背景知识
安全护栏通常是在短文本上训练和评估的分类器或过滤器，用于识别大模型输入或输出中的有害内容。长上下文可能使关键有害信号被大量正常文本稀释，降低检测灵敏度。“针在干草堆”测试原本用于评估模型在长文本中检索特定信息的能力，LongGuard 将其扩展为安全场景。
关键细节
SafetyNIAH 任务用 0.25k-32k 长度网格系统评估护栏；注意力- logit -行为三层分析在控制长度变量后仍保持一致链条，并分离出一组相对于基础模型具有部分特异性的护栏专用检索头。CAHR-CD 采用分块检测以保持针密度，CAHR-AHS 锐化注意力头，CAHR 按上下文长度和审计侧路由选择配置。

OBPE边界执行将智能体违规率从57.6%降至0.2%

rss ArXiv cs.AI · 2026-08-31 · ⌛ 2 分钟阅读
评分依据：Presents a novel technical mechanism for agent governance that addresses critical security and overprivilege risks, with formal guarantees; high relevance for AI practitioners and enterprise deployment, though limited market/economic signal.
📰 发生了什么
研究人员发布了带外策略执行（OBPE）机制，将可信边界置于智能体推理之外，授权类型化操作和资源、在后端调用前收窄查询，并对响应中的记录和字段进行过滤或值掩码。数据策略所有者设定最大授权，智能体策略只能进一步收窄。团队发布了一个基于类型化 Cedar 策略核心的 HTTP 代理原型，并通过一致性测试将策略模型与智能体连接。在针对 Jira 和 ServiceNow 模拟环境、四个模型和 20 个自适应红队任务的 3,621 次试验中，受保护数据进入智能体上下文、精确值泄露或禁止效果完成的比例从 57.6% 降至 0.2%，成对的安全有用完成率上升 21.8 个百分点。
💡 为什么重要： 该机制解决了智能体继承人类凭据时的过度授权风险：智能体可能将每个可达记录吸入上下文或吸收秘密，而每个请求仍然凭据有效。OBPE 在易出错的推理模型之外创建确定性执行点，使企业能够按策略所有者设定的最大范围向智能体开放 Jira 或 ServiceNow 等工具，而不是依赖提示指令。智能体策略无法扩大上限这一形式化结果，为受监管或生产部署提供了治理保证。
📊 关键数据: 57.6% 0.2% 3,621
背景知识
Cedar 是一种开源策略语言，用于授权表达，常用于 AWS 服务权限管理。获得人类凭据的智能体会继承该凭据的全部访问范围，却没有限制其使用的人类判断，因此基于提示的限制不可靠——同一个推理模型既要解释任务，又要执行自身限制。带外执行将策略检查放在模型上下文和决策循环之外的独立可信代理边界中。
关键细节
OBPE 的策略核心采用 Cedar 策略语言，并围绕类型化操作和资源组织；代理在后端调用前收窄查询，并可根据参数值或外部状态语义拒绝或暂缓已授权调用。字段移除只覆盖一次执行，掩码和历史规则的保证较弱，写控制、持久审批以及时间或聚合策略不在本次评估范围内。在所述条件下，策略计划与顺序无关，且智能体策略无法扩大所有者设定的上限。

📰 发生了什么
研究者提出用拉希测量理论(RMT)将LLM评估分解为可分离的多个维度，并在“测量仇恨言论”语料库上对九个LLM的标注拟合多面拉希模型。分析显示，这些LLM在严重程度、项目级校准、问题顺序稳健性、目标身份敏感性和评分量表使用上均与人类评分者存在系统性差异。这些差异在标准评估实践中会被掩盖。
💡 为什么重要： 当前LLM基准测试常将得分视为单一整体，忽略评分者与题目维度的贡献。RMT提供的诊断工具能识别校准失准和评分者偏差，提升AI评估的可靠性。对于构建LLM-as-judge流程的工程师以及需要评分一致性的仇恨言论检测场景，该方法具有直接实用价值。
背景知识
拉希测量理论源自心理测量学，属于项目反应理论的一种，通过同时估计题目难度、对象能力和评分者严重度，将序数评分放在统一尺度上。LLM-as-rater指用大语言模型为其他模型输出或人类内容打分，可能引入系统性偏差。“测量仇恨言论”语料库是一个经过RMT验证构念的仇恨言论数据集。
关键细节
拉希测量理论将序数评分分解为共同尺度上的可分离维度，多面拉希模型能够同时估计对象能力、题目难度与评分者严重度。研究者使用“测量仇恨言论”语料库，其构念本身基于RMT构建，对九个跨家族和能力水平的LLM标注进行拟合。诊断指标揭示了LLM在项目级校准和评分量表使用等方面与人类的差异。
