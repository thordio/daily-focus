CALM：文本到图像生成全局不安全信号局限及局部防护

rss ArXiv cs.AI · 2026-10-05 · ⌛ 2 分钟阅读
评分依据：Provides a novel technical analysis and counterfactual method for AI safety in text-to-image generation, relevant to practitioners; no community discussion signals available.
📰 发生了什么
对文本到图像生成模型的全局不安全信号进行受控几何分析后发现，存在覆盖-选择性权衡：紧凑的不安全子空间无法覆盖异构不安全语义，而更广的聚合会扭曲安全相关的良性提示。研究者提出CALM（Counterfactual Adaptive Local Modulation），一种训练无关的提示局部安全防护方法，用匹配的不安全-良性锚点将每个提示路由到活跃不安全类别，仅对违规token表示向安全侧进行最小编辑，并抑制正对齐的不安全残差分量。
💡 为什么重要： 对于部署文本到图像生成模型的内容平台和开发者，CALM提供了一条无需重训练或微调即可提升不安全内容抑制效果的途径，同时保持良性输出质量。在当前AI安全监管趋严的背景下，该方法有助于减少全局安全信号带来的过度过滤和漏检问题，降低合规风险。
背景知识
文本到图像模型将文本提示映射为图像，恶意提示可能生成不安全内容。训练无关安全防护通常预计算一个可复用的全局安全方向或毒性子空间，并将其应用于所有提示。CALM改为针对每个提示的活跃不安全类别进行自适应校正，旨在克服全局信号的覆盖与选择性局限。
关键细节
CALM采用训练无关设计，用提示局部的反事实校正替代统一的全局不安全信号去除。它使用匹配的不安全-良性锚点进行路由，仅对违规token表示进行最小编辑，并抑制正对齐的不安全残差分量，从而避免扭曲安全相关的良性提示。

DeReAct 分解 ReAct 代理，增加外部 Critic 与 Context Manager 门控

rss ArXiv cs.AI · 2026-10-05 · ⌛ 2 分钟阅读
评分依据：Introduces a modular agent architecture with external gating that improves Pass@1 on GAIA and SWE-bench, especially for weaker models; technically novel and relevant, but incremental rather than a fundamental breakthrough. No community discussion provided.
📰 发生了什么
DeReAct 引入模块化代理架构，将两个门控策略外部化：Critic 在执行前验证拟议动作，Context Manager 重建环境支持的 State 并认证任务完成。在 GAIA 和 SWE-bench Verified 上，DeReAct 对较弱 Brain 模型的 Pass@1 提升最大：Qwen3-Coder-480B 提升 6.5-7.0 个百分点，Claude Sonnet 4.5 提升 4.2-5.2 个百分点；随着 Brain 能力增强，增益递减。使用 Claude Opus 4.5 时 Pass@1 与 ReAct 相当，但轨迹更具证据完整性和约束满足性。
💡 为什么重要： 这一解耦使动作授权和完成控制可以独立于主策略执行，避免错误传播和未获支持的完成声明提前终止任务。对于使用较弱 LLM 构建代理的团队，外部门控可在不更换 Brain 模型的情况下提升单次通过率，并可能用早期终止换取更强的证据支持。该架构表明模块化门控是提升代理可靠性的实用路径，尤其适用于成本敏感或模型能力有限的部署场景。
📊 关键数据: 6.5 7.0 4.5
背景知识
ReAct 是一种推理与行动交替的代理方法，通常由单一 LLM 策略负责提出动作、与环境交互并判断何时完成。GAIA 是评估通用 AI 助手能力的基准，SWE-bench Verified 是软件工程任务基准。单一策略的耦合使得动作授权和完成判断难以独立强制，错误可能累积。DeReAct 通过外部 Critic 和 Context Manager 将这两个环节解耦。
关键细节
DeReAct 的外部 Critic 策略在每个拟议动作执行前进行验证，Context Manager 策略重新构建环境支持的 State 并认证完成条件，二者与 Brain 主策略分离。轨迹和消融分析显示，外部门控在目标故障足够普遍且门控策略本身足够强时有效；随着 Brain 能力增强，增益递减，但在 Claude Opus 4.5 上仍保留证据完整性和约束满足性优势。

FlashSinkhorn 2 单GPU 2.5小时求解1.34亿粒子最优传输

rss ArXiv cs.AI · 2026-10-05 · ⌛ 2 分钟阅读
评分依据：Presents a substantial algorithmic improvement for large-scale entropic optimal transport on GPUs, which is relevant to AI/ML practitioners using OT for applications like generative modeling. Technical depth is high, but it is an incremental advance over prior FlashSinkhorn rather than a paradigm shift. No comments or engagement signals provided.
📰 发生了什么
FlashSinkhorn 2（FS2）是一个面向低维点云平方欧氏代价熵最优传输的两阶段GPU求解器。粗阶段在单元质心上求解，将势函数提升到每个点，并通过采样边际检查决定是否继续在质心上迭代以替代大部分点级更新。块稀疏细阶段使用Morton排序块，支持筛选和融合张量核心执行，并用块质量设定的阈值约束每个省略块对每行每列的贡献。在一块A100上，FS2对来自宇宙学N体模拟的两个1.34×10^8粒子测度进行离散EOT求解，在熵模糊等于平均粒子间距的条件下，全粒子边际残差低于0.01，耗时不到2.5小时；在32个合成基准和10个GeomLoss多尺度基准上达到目标残差。
💡 为什么重要： 这使得在单GPU上求解高精度熵最优传输达到前所未有的规模，为将OT用于生成建模、领域适配和科学数据分析的AI/ML从业者降低了内存和计算需求。FS2避免存储稠密核并减少大部分点级更新，使上亿粒子的高精度EOT（如宇宙学N体模拟或单细胞基因组学）变得可行。开源实现降低了研究人员在没有多节点基础设施的情况下将块稀疏OT应用于大规模问题的门槛。
📊 关键数据: 1.34 0.01 2.5
背景知识
熵最优传输（EOT）在两种概率测度之间寻找低代价耦合，并加入熵正则化项；Sinkhorn迭代是标准方法，但需要计算n×m核矩阵。稠密核的评估和存储对大规模点云难以承受，之前的流式求解器如FlashSinkhorn虽然避免存储，但仍需评估所有点对。块稀疏方法通过跳过贡献可证明可忽略的块来减少计算，而Morton排序改善数据局部性。低维点云上的平方欧氏代价在物理学、生物学和生成建模中常见。
关键细节
FS2的粗阶段使用单元质心和采样边际检查来替代大部分点级更新，细阶段用Morton排序块校正质心误差。由块质量设定的阈值限定了每个被省略块对每行每列的贡献，从而支持筛选和融合张量核心执行。求解器以规定的边际残差为目标，而不是固定的迭代次数。
