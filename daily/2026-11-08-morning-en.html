These files were manually created and committed to public repositories, not automatically generated by Claude Code, which normally adds the file to .gitignore. The exposed configurations contain commands that include secrets such as API keys and passwords directly in the command text. Anthropic's Boris from the Claude Code team acknowledged the issue, stating the team is looking into prevention while noting the file is meant to stay local.
💡 Why It Matters： Developers who use Claude Code and publish repositories risk exposing credentials if they commit .claude/settings.local.json, potentially compromising APIs, databases, or cloud services. The finding underscores how AI coding agents can increase secret leakage risk when convenience features like 'Don't Ask Again' store sensitive command strings. Anthropic's response signals potential future mitigations but places current responsibility on developers to avoid committing the local settings file.
📊 Key Facts: 1,122
Background
Claude Code is Anthropic's AI coding assistant that runs in the terminal. The 'Don't Ask Again' option lets users approve a command once so that Claude Code executes it without further prompts; the full command, including any embedded secrets, is stored in .claude/settings.local.json. This file is intended only for the local machine and contains user-specific permissions and command approvals. Public GitHub repositories are searchable, so any committed file with credentials is exposed to anyone.
Key Details
Claude Code historically does not perform secret scrubbing; secrets embedded in approved commands remain in plaintext in the settings file. The exposed files were found in public GitHub repos, indicating developers manually created and committed the file rather than relying on automated gitignore.
