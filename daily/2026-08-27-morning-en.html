Agent Trace Automata Distill LLM Agent Behavior into Compact FSMs

rss ArXiv cs.AI · 2026-08-27 · ⌛ 5 min read
Reason：Novel method collapsing LLM agent traces into compact finite-state machines improves next-step and failure prediction, addressing opacity in agent behavior for safety and monitoring; technical depth high, but no community discussion provided to validate impact.
📰 What's New
Researchers introduced a method that collapses entire LLM agent trace corpora into single compact finite-state machines (FSMs). Across twelve public datasets, the resulting FSMs have 7–43 states and replay held-out data at ≥0.997 fitness with near-identical topology across splits, building in milliseconds. FSM-state context outperforms Agent Workflow Memory on every ground-truth-matched dataset for next-step prediction. For failure prediction, per-state behavioral features reach held-out AUROC up to 0.94, and an online monitor ranks failing runs above passing ones from a partial trace, triggering early stopping well before completion.
💡 Why It Matters： The work addresses opacity in LLM agent behavior for safety auditing and runtime monitoring, where long unstructured traces resist deployment requirements. The compact FSM substrate gives a model-agnostic structural primitive, meaning safety teams can audit and monitor multi-step agents without depending on a particular LLM. The finding that behavioral topology is shaped more by deployment harness than by the LLM suggests operators can reuse infrastructure-level models across different models.
📊 Key Facts: 0.997 0.94
Background
LLM agents are systems that use large language models to take multi-step actions, producing sequences called traces. A finite-state machine (FSM) models behavior as a limited set of states and transitions, offering compactness over raw traces. Agent Workflow Memory is a prior method that stores workflow steps to guide agents. AUROC (area under the receiver operating characteristic curve) measures how well a classifier ranks failing versus passing runs, where 1.0 is perfect.
Key Details
The method compresses an entire trace corpus into a single FSM, with 7–43 states across twelve datasets, achieving ≥0.997 replay fitness on held-out data. For next-step prediction, FSM-state context beats Agent Workflow Memory on all ground-truth-matched datasets. The online failure monitor uses per-state behavioral features to reach AUROC up to 0.94 and can trigger early stopping before task completion.

ESQ-Bench Shows NL2SQL Models Struggle on Enterprise Oracle Schemas

rss ArXiv cs.AI · 2026-08-27 · ⌛ 5 min read
Reason：The paper introduces a valuable enterprise-focused NL2SQL benchmark with multi-database support and evaluation of silent semantic divergence, revealing significant performance degradation of GPT-4o on complex schemas. This has practical implications for AI practitioners and researchers working with text-to-SQL systems.
📰 What's New
ESQ-Bench is introduced as an Oracle-first NL2SQL benchmark with six populated schemas, 465 tables, 164,682 rows, and 550 gold-validated question-query pairs across three complexity tiers. Schema-linked prompting with GPT-4o achieves only 79.8%, 60.3%, and 57.2% execution match across tiers, while EM stays below 7% and silent divergence reaches 73% to 99% among EX-passing queries. Claude Sonnet 4.6 reaches 87.4%, 74.9%, and 68.7% execution match with schema-linked prompts, exceeding GPT-4o on every tier. Local Llama 3.2 schema-linked reaches only 13.3% bank-wide execution match (73 out of 550).
💡 Why It Matters： The benchmark reveals that state-of-the-art NL2SQL models, which report over 89% execution accuracy on Spider and BIRD, degrade sharply on enterprise Oracle schemas with silent semantic errors, undermining trust in production text-to-SQL deployments. Enterprise AI teams using GPT-4o or similar closed models face accuracy drops of over 40 percentage points and silent divergence up to 99%, meaning queries may return wrong results without error and require additional validation layers. The gap between closed API models and open-weight baselines like Llama 3.2 highlights the need for enterprise-grade fine-tuning or schema-aware prompting.
📊 Key Facts: 79.8% 60.3% 57.2%
Background
NL2SQL (Natural Language to SQL) converts natural language questions into SQL queries; academic benchmarks like Spider and BIRD use simplified schemas, typically one database with clear foreign keys. Enterprise Oracle schemas often include complex data types, partitions, stored procedures, security constraints, and many tables/columns, making translation much harder. 'Silent semantic divergence' refers to generated SQL that executes without syntax errors but returns incorrect results due to misunderstood schema semantics or business logic, which is riskier than visible execution errors.
Key Details
The benchmark uses four evaluation metrics: exact match (EM), execution match (EX), success rate (SR), and silent divergence (SD), and supports Oracle, PostgreSQL, MySQL, and SQL Server with identical seed data. GPT-4o zero-shot execution match is 78.7%, 73.5%, and 77.8%, which inverts schema-linked performance at tiers 2 and 3 due to lower zero-shot execution rates and survivor bias. Failure analysis shows wrong-result semantics dominate at higher complexity tiers.

STEP-KTODER Adds Function-Level Execution Feedback to Code Preference Optimization

📰 What's New
Researchers introduced STEP-KTODER, a framework that defines steps as module-level functions in decomposed multi-function programs and assigns binary correctness labels via automatically generated unit tests. It combines function-level process supervision with outcome-level feedback on the full program. Evaluations on HumanEval(+), MBPP(+), BigCodeBench, and LiveCodeBench show improvements over outcome-only KTO and DPO. The team also found that LLM-as-a-judge annotations systematically over-predict function failures, corrupt positive step labels, and degrade preference optimization.
💡 Why It Matters： Process supervision for code generation has lagged behind math because code lacks a standard step unit; STEP-KTODER shows execution-based function labels can close that gap. This could improve alignment and reliability of code LLMs in real-world multi-function programs, where unit tests are often already available. It also warns against using LLM-as-a-judge for fine-grained code feedback, because annotation errors directly degrade optimization.
Background
KTO and DPO are preference optimization methods that train language models to prefer chosen outputs over rejected ones; outcome-only variants apply this at the whole-program level. Process supervision instead gives feedback on intermediate steps, which has improved mathematical reasoning. Code generation typically lacks a natural step unit, so STEP-KTODER proposes module-level functions as steps and uses unit tests to label them.
Key Details
STEP-KTODER instantiates stepwise KTO for code by using decomposed multi-function programs; each module-level function is treated as a step. It assigns binary correctness labels from automatically generated unit tests rather than LLM judgments. The paper reports improvements over outcome-only KTO and DPO on HumanEval(+), MBPP(+), BigCodeBench, and LiveCodeBench.

Study Finds 96.7% of LLM-Generated Autobiography Scenes Fail Verification

rss ArXiv cs.AI · 2026-08-27 · ⌛ 5 min read
Reason：First quantified scene-level audit of LLM-generated autobiography shows a 96.7% verification failure rate, providing concrete evidence of severe confabulation. Relevant to AI reliability and trust, though scope is narrow (autobiography). No community discussion provided.
📰 What's New
An audit of a 366-day page-a-day memoir generated with a conversational LLM found that 354 of 366 days failed verification, a 96.7% failure rate (Wilson 95% CI 94.4–98.1%). The author and subject were the same person; generation inputs were a template, two exemplar days, and each day's quote, not her corpus. Only 12 days contained a corroborated scene, while 19 days (5.2%) made claims actively contradicted by the record; the dominant failure mode was grounded drift, where real people, employers, and settings appear in invented scenes. Regeneration with current named models reproduced 100% verification failure under identical inputs, and grounding generation in the subject's corpus still left 83.3% residual failure.
💡 Why It Matters： This provides the first quantified scene-level evidence that LLM autobiography generation is overwhelmingly confabulated, with 96.7% of scenes unverifiable and 83.3% residual failure even after grounding. The finding directly affects applications such as memoir assistance, biography drafting, and any summarization of personal records where users may mistake fluent output for factual record. It signals that current models cannot reliably produce true personal narratives without stronger retrieval or verification mechanisms.
📊 Key Facts: 96.7% 95% 98.1%
Background
LLM confabulation refers to the generation of fluent but factually incorrect statements. A verification corpus is an independent record of a person's life used to check generated claims. A page-a-day memoir is a diary format with one entry per day. Grounded drift occurs when real people, employers, or locations are inserted into events that never happened.
Key Details
The study used a four-level rubric (VERIFIED, WEAK, UNVERIFIED, CONTRADICTED) fixed before analysis and defined verification-failure rate as days not rated VERIFIED. Independent re-rating replicated the 96.7% headline while showing the four-way taxonomy has only fair-to-moderate reliability, and the WEAK/UNVERIFIED boundary was unreliable. Regeneration under the same inputs with current models yielded 100% failure, while grounding generation in the subject's corpus significantly improved verification but left 83.3% residual failure.

Study Isolates Model vs Instrument Effects in AI Preference Measurements

rss ArXiv cs.AI · 2026-08-27 · ⌛ 4 min read
Reason：Deep methodological analysis addressing inconsistencies in AI preference measurement, relevant to AI safety and alignment researchers; no community discussion provided.
📰 What's New
Researchers held outcomes and models fixed while varying only the prompt instrument, using 8 models, 15 outcomes, and 5 instruments in 11,400 scored elicitations. The ranking a model gives the 15 outcomes generalises across instruments at a generalisability coefficient of 0.348, and raising that coefficient to 0.80 would require about 38 instruments. Four of the 15 outcomes show no variance separating one model from another. An estimate of 87.6 percent survives removal of any one instrument, any one model, and four outcomes whose scales vary, remaining within 0.777 to 0.934 and exceeding the null distribution's 95th percentile of 0.365.
💡 Why It Matters： A preference obtained from one instrument carries little information about what a second instrument would report, undermining cross-study comparisons in model welfare and AI safety research. Researchers and policymakers relying on single-instrument preference elicitation may draw conflicting conclusions about model welfare without this methodological control.
📊 Key Facts: 11,400 0.348 0.80
Background
Model welfare research infers what a model prefers from answers returned to prompts written to elicit preferences. Prior studies from Keeling et al. (2024), Mazeika et al. (2025), Mikaelson et al. (2025), Tagliabue and Dung (2025), and Trhlik et al. (2026) reached disagreeing findings because no two held outcomes, models, and instruments fixed simultaneously. A prompt instrument is a specific format for asking a model about its preference.
Key Details
The design used five instruments repeated five times each across 15 outcomes, with four outcomes reusing published prompts verbatim and five filling the stimulus slot of a published template. Robustness checks removed each instrument and each model in turn, plus four outcomes whose scale varies probability, delay, duration, or count instead of intensity. Generalisability coefficients and null-distribution percentiles were used to isolate variance sources.
