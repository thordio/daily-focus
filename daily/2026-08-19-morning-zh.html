MoNe模块化神经记忆在128K tokens下将长上下文推理成本降低80%

rss ArXiv cs.AI · 2026-08-19 · ⌛ 2 分钟阅读
评分依据：Novel modular neural memory architecture attaches to frozen transformers, achieving O(1) query cost and ~80% compute/memory reduction at 128K tokens, a potentially paradigm-shifting advance for long-context inference. No community discussion available.
📰 发生了什么
MoNe是一种轻量级模块化神经记忆，可附加到任何冻结的预训练Transformer上，无需重新训练即可实现长上下文推理。它通过测试时学习带有层局部梯度更新的快速权重神经记忆网络，以固定大小分段读取上下文。推理时记忆仅从查询token生成键和值，不再重新读取上下文token。在128K tokens时，MoNe相比上下文学习将计算和峰值GPU内存降低约80%，参数开销仅6.4%。
💡 为什么重要： 这一设计将推理成本与上下文长度解耦，使原生窗口较小的模型也能处理超长文档和多文档问答等任务，而无需线性增长的内存。对运行大模型推理的企业而言，128K tokens下可削减约80%的GPU内存和计算成本，可能支持更大的批处理规模和更便宜的长上下文服务。O(1)查询成本可能改变长上下文推理的部署方式，让上下文窗口较小的模型在RULER基准上具备竞争力。
📊 关键数据: 80% 6.4%
背景知识
上下文学习（ICL）会在每一步将整个上下文输入Transformer的注意力机制，因此计算和内存随上下文长度N线性增长。快速权重记忆网络通过在测试时更新参数来存储信息，而不是向输入添加token。冻结的预训练Transformer权重固定，通常受限于训练时的上下文窗口。RULER是用于评估长上下文语言模型的基准，包含针堆搜索和词提取等任务。
关键细节
MoNe采用两阶段设计：O(N)预处理以固定大小分段读取上下文，并通过层局部梯度更新学习快速权重神经记忆网络；查询阶段为O(1)成本，因为记忆仅从查询token生成键和值。峰值GPU内存不随N增长。该架构仅增加6.4%的参数开销，且能泛化到远超骨干网络原生窗口的上下文长度，在RULER的针堆搜索和词提取基准上表现强劲。

Agent Lightning v1.0 发布 harnessed 智能体强化学习框架

rss ArXiv cs.AI · 2026-08-19 · ⌛ 2 分钟阅读
评分依据：Important technical progress in agentic RL infrastructure, introducing a harnessed training paradigm adopted by multiple frameworks; high relevance for AI practitioners building or training agents, though no community discussion provided.
📰 发生了什么
Agent Lightning v1.0 是一个约3500行代码的轻量级框架，用于 harnessed 智能体强化学习。它支持任意智能体 harness，并解决 retokenization、样本合并、优势计算、损失归一化和后端调度等挑战。该框架在指令遵循、搜索和编码智能体上进行了评估。在可复现的编码智能体 RL 流程中，仅用 6000 个训练样本就将 Qwen3.5-9B 在 SWE-bench Verified 上的成绩从 41.8% 提升到 56.4%，绝对提升 14.6 个百分点。
💡 为什么重要： 通过让部署时 harness 拥有环境交互循环，Agent Lightning v1.0 使开发者几乎无需修改代码就能为现有 AI 智能体添加强化学习能力。verl Uni-Agent、AReaL 2.0、slime 和 Polar 等框架已经采用这种 harnessed 范式。仅用 6000 个样本就在 SWE-bench 上提升 14.6 个百分点，说明较低成本的 RL 训练也能为编码智能体带来显著收益。
📊 关键数据: 41.8% 56.4% 1.0
背景知识
Agent harness 是管理 LLM 驱动智能体的工具、上下文和控制流的运行时。传统智能体强化学习将训练与环境紧密耦合，通常需要修改代码。Harnessed 智能体强化学习则让部署时 harness 掌控交互循环，训练端只看到请求-响应序列。SWE-bench Verified 是一个基于真实 GitHub 软件工程问题的基准，用来衡量 LLM 的编码能力。
关键细节
原始 Agent Lightning 采用解耦架构，通过 LLM 端点代理将任意智能体连接到强化学习训练；v1.0 保持由 harness 掌控循环，而训练器只观察 LLM 请求-响应对序列。这种训练数据格式需要自定义处理 retokenization、样本合并、优势计算、损失归一化和后端调度。发布的编码智能体 RL 流程包含完整训练脚本，便于复现研究。

Aegis：智能体AI运行时行动边界治理

rss ArXiv cs.AI · 2026-08-19 · ⌛ 2 分钟阅读
评分依据：Introduces a concrete runtime governance system for agentic AI safety, addressing a critical gap between prompt-level control and execution. High technical relevance for AI practitioners, but no community discussion or adoption evidence yet.
📰 发生了什么
研究人员推出了 Aegis，一个面向智能体AI的运行时治理系统，通过可信决策层调解工具行动。在包含5个运行家族、42个任务、3种条件和每个家族10次重复的沙盒语料中，提示策略条件在6,300行中产生了79行有风险的比较路径泄漏；而2,100行由Aegis治理的记录中，受治理的模拟工具应用为0，受治理的有风险副作用完成为0。全部1,832行Aegis尝试治理的行保留了可信的Aegis解析溯源，全部1,019行参议院式裁定行具备法定人数和最终签名计票证据。模型提出提议，可信运行时做出决定。
💡 为什么重要： 安全问题的重点从生成有害文本转向有害操作副作用，意味着智能体AI系统需要运行时执行边界，而不只是提示级控制。Aegis 的故障关闭和基于法定人数的参议院式裁定，在模型提议与工具执行之间提供了可强制执行的关卡，有望减少生产环境中未经授权的文件修改、消息发送、作业启动或工作流状态变更。2,100行治理记录中零个有风险副作用完成，为AI安全从业者提供了审计和约束智能体工具使用的具体机制，但结果仅限于沙盒语料。
📊 关键数据: 6,300 2,100 1,832
背景知识
智能体AI系统不仅生成文本，还会请求修改文件、发送消息、启动作业和更改工作流状态等工具行动。提示级治理可以影响模型行为，但不会在执行边界上阻止模型产生有害工具调用。此处的溯源指关于行动提议来源及授权方式的可验证记录。参议院式裁定借鉴立法机构法定人数规则，要求多个独立授权方而非单一决策点，因此任何一方都无法单方面批准有风险行动。
关键细节
Aegis 将模型输出视为行动提议，并根据活动策略状态评估这些提议，在工具执行前在服务器端解析溯源。它在不确定情况下故障关闭，并将选定案例路由至参议院式裁定——一种基于法定人数的非单方授权路径，需最终签名计票证据。评估使用包含5个运行家族、42个任务、3种条件和每个家族10次重复的重复沙盒语料，产生6,300行提示策略行和2,100行Aegis治理行。

研究人员构建了名为FAR（Find, Attempt, Recommend）的文献到评审级联系统，专家只需提供研究方向而非预先选定的问题。在一个组合数学试验中，FAR处理了5,245篇组合数学论文，提取出6,453个候选猜想或开放问题，并过滤得到4,717个表述良好且仍未解决的猜想。随后的自动推理和分诊阶段浮现出598个潜在解决方案，其中77个被选入作者团队评审。该流程在Davies–Jenssen–Perkins–Roberts、Erdős–Straus、Ikenmeyer–Pak–Panova和Lund–Saraf–Wolf等人的猜想和问题上得到了结果。

DiSCO：通过分布引导对比提示优化防御文本到图像生成

rss ArXiv cs.AI · 2026-08-19 · ⌛ 2 分钟阅读
评分依据：Novel zero-shot black-box defense for text-to-image safety addresses the identified benign adversarial problem, offering practical applicability to proprietary models without retraining or internal access; no community discussion provided.
📰 发生了什么
研究人员提出 DiSCO，一种零样本、严格黑盒的提示级防御模块，可即插即用地用于任意文本到图像系统，无需重新训练或访问模型内部。DiSCO 通过束搜索执行分布引导的后缀扩展，并对目标模型自身生成的安全与不安全图像池进行对比评分，以迭代自适应反馈直到产生安全内容。在 I2P 基准上，DiSCO 使未防御模型和已防御模型的攻击成功率分别降低 37.7% 和 25.13%，同时保持语义保真度并改善图像连贯性。该模块架构无关，无需对模型本身做任何改动。
💡 为什么重要： 现有文本到图像安全防御多依赖白盒假设，无法扩展到闭源或专有模型，而基于大语言模型提示重写的黑盒方法在“良性对抗”场景下会失效。DiSCO 证明了在完全不访问模型内部的情况下，仅通过提示词优化即可显著降低 NSFW 内容生成风险，为部署在 API 背后的商用图像生成服务提供了实用的安全增强路径。这对需要遵守内容安全法规的平台和希望保护品牌安全的图像生成 API 提供商尤为重要。
📊 关键数据: 37.7% 25.13%
背景知识
文本到图像生成模型可能会在提示词诱导下生成暴力、裸露等不适宜工作场合（NSFW）内容。白盒防御需要访问模型参数、梯度或内部表示，而黑盒防御只能通过输入输出交互。红队攻击指故意构造提示词以绕过安全机制；DiSCO 针对的“良性对抗”问题是指提示词在语言层面看似安全、但仍因模型学到的数据分布而触发有害生成。
关键细节
