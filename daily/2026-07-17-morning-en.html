OriginBlame cuts machine unlearning over-deletion from 101x to 1.3x

rss ArXiv cs.AI · 2026-07-17 · ⌛ 4 min read
Reason：Addresses a critical practical gap in AI data management (right to be forgotten) with a novel system that significantly reduces over-deletion and improves unlearning. The evaluation is rigorous, and the improvements (e.g., over-deletion reduction from 101x to 1.3x) are substantial. Although not a paradigm-shifting breakthrough, it provides high practical value for developers and companies handling training data compliance. No community discussion provided to factor in.
📰 What's New
Researchers developed OriginBlame (ob), a provenance system that tracks author identity at record and token level through data processing pipelines. Evaluation on 219,555 Wikipedia pages shows that record-level provenance slashes over-deletion from 101x (dataset-level) to 1.3x. Integration with HuggingFace and Datatrove pipelines incurs only 1.3-4.0% and 2.1-19.0% throughput overhead, respectively. On a 1.7B parameter model, provenance-based forget sets improve unlearning efficacy by 42% compared to random baselines.
💡 Why It Matters： When individuals request data removal under regulations like GDPR, model trainers must delete their data's influence, a process known as machine unlearning. Without provenance, forget sets are entire datasets, leading to massive over-deletion and model degradation. OriginBlame provides the missing tool to precisely identify an author's data at record and token level, making unlearning practical for real-world compliance.
📊 Key Facts: -4.0% -19.0% 42%
Background
Machine unlearning aims to remove the influence of specific training data from an AI model without full retraining. Data provenance tracks the origin and transformation of data through a pipeline. The right to be forgotten, enshrined in regulations like GDPR, requires data controllers to erase personal data upon request, but for AI models this is challenging because training data is intermixed. Dataset-level provenance forces deletion of entire datasets, causing excessive data loss; fine-grained provenance allows pinpointing only an author's contributions.
Key Details
OriginBlame propagates author identity by instrumenting data processing steps like filtering, deduplication, and tokenization, using deterministic queries to resolve revocation requests into precise forget sets. The system introduces low overhead: 1.3-4.0% on HuggingFace and 2.1-19.0% on Datatrove pipelines. Unlearning improvements were measured on a 1.7B model using a 42% boost over random baselines.

rss ArXiv cs.AI · 2026-07-17 · ⌛ 4 min read
Reason：Novel framework addressing critical issue of agent error recovery with potential to improve efficiency and reliability; represents important technical progress in AI agent design.
📰 What's New
Researchers proposed Experience Memory Graph (EMG), a framework that reformulates LLM agent failure recovery as a graph matching problem. It converts failed and successful trajectories into directed action decision graphs, then matches them to extract common subgraphs and graph edit paths that explicitly indicate corrections (e.g., add, delete, or relabel actions under given observations). These are stored in a memory graph with intra-task nodes and cross-task edges, enabling one-shot error correction at test time without iterative loops. On ALFWorld and ScienceWorld benchmarks, EMG consistently outperforms state-of-the-art reflection baselines in both success rate and average reward.
💡 Why It Matters： This addresses a critical bottleneck for LLM agents in long-horizon tasks: compounding errors and expensive iterative self-correction. By enabling one-shot error recovery, EMG reduces computational and API costs while improving agent reliability, which could accelerate the deployment of autonomous agents in complex real-world applications like robotic control and virtual assistants.
Background
LLM agents generate sequential trajectories of states, actions, and observations. In complex tasks, small errors compound and lead to failure. Existing self-correction methods rely on prompt-based reflection with iterative loops that are costly and produce task-specific fixes that don't generalize. EMG replaces this with a graph memory that captures reusable correction patterns, enabling immediate recovery.
Key Details
The approach converts trajectories into directed action decision graphs, then uses graph matching to derive graph edit paths—explicit instructions to add, delete, or relabel actions. The memory graph stores these with cross-task edges, allowing retrieval of relevant failure-correction knowledge in a single forward pass. Experiments on ALFWorld and ScienceWorld show EMG surpasses prompt-based reflection methods without any test-time trial-and-error.

📰 What's New

💡 Why It Matters： This black-box method enables auditing of LLM reasoning for genuine premise dependency, critical for AI safety and trust in high-stakes applications. It uncovers hidden reasoning flaws even when outputs are correct, challenging assumed chain-of-thought fidelity, and offers a scalable evaluation approach without requiring model internals.
📊 Key Facts: 100% 66% 0.806
Background
ProntoQA is a benchmark for multi-hop deductive reasoning where each problem has a known proof tree showing premise dependencies per step. Chain-of-thought reasoning is a prompting technique where models generate intermediate steps. Auditing this reasoning for factual grounding is vital for AI safety, but existing methods often need internal model access or have lower accuracy.
Key Details
The intervention replaces a premise's target predicate with a fresh symbol, then checks if each step's normalized conclusion (canonical predicate form) changes. Evaluation used ProntoQA, a synthetic deductive reasoning benchmark with gold proof trees, and the GPT-4o model. Entity-introduction premises were identified as a blind spot for the consistent-substitution evaluator.
