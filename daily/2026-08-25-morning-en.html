Gemma4-31b Scores 31–89% Across 26 Harness Configurations in LLM Benchmark Study

rss ArXiv cs.AI · 2026-08-25 · ⌛ 5 min read
Reason：This paper presents a systematic analysis showing that LLM leaderboard rankings are highly sensitive to evaluation harness configurations, providing critical evidence that current benchmark comparisons may be unreliable. This is important for AI practitioners and researchers who rely on leaderboards for model selection and comparison.
📰 What's New
A matched comparison fixed 3,679 items from ARC, HellaSwag, MMLU, and TruthfulQA, along with weights and greedy decoding, while varying only the evaluation harness across 26 equally defensible configurations for 12 open-weight instruction-tuned LLMs from 4 families. Under this grid, gemma4-31b's score ranged from 31% to 89% purely from harness changes. Config-fragile items carried 95.7% of the average score gap between adjacent models, and four of the 12 models reached rank one under some configuration. Scoring choice, not option order, was the load-bearing axis; item discrimination correlated with fragility at 0.28 (95% CI 0.25 to 0.30).
💡 Why It Matters： Leaderboard rankings used for model selection can be manufactured by harness choices; a model's position becomes a band rather than a point, so decisions based on these rankings may be unreliable. The 95.7% gap attribution to config-fragile items means even adjacent model comparisons often reflect harness artifacts rather than capability differences. Releasing per-item records and a reproducible script enables leaderboard maintainers to run fragility checks before reporting an order.
📊 Key Facts: 31% 89% 95.7%
Background
Standard LLM multiple-choice benchmarks fix the questions and correct answers but leave the evaluation harness unspecified: option order, prompt wording, and whether answers are read from generated text or per-option likelihoods can all vary. Previous work reported aggregate score variance from harness changes but did not examine which items account for the differences. This study treats the harness as an independent variable while keeping models, items, weights, and greedy decoding fixed, enabling per-item attribution. ARC, HellaSwag, MMLU, and TruthfulQA are widely used multiple-choice benchmarks in language model evaluation.
Key Details
The fragility grid records one correctness bit for every model, item, and configuration, resolving harness sensitivity to single items. Adjacent model pairs tie on items both answer stably, while config-fragile items carry 95.7% of the pair's gap on average. Benchmark-compression methods maximize item discrimination, but discrimination correlates with fragility at 0.28 (95% CI 0.25–0.30), so compression retains fragile items. The scoring choice—generated text versus per-option likelihoods—is the load-bearing axis, not the option order that protocols usually fix.

KVBoost Achieves 4.49x Faster LLM Prefill via Chunk-Level KV Cache Reuse

rss ArXiv cs.AI · 2026-08-25 · ⌛ 5 min read
Reason：Proposes a novel chunk-level KV cache reuse method with dual-hash and repair strategies, addressing a key inference cost bottleneck; technical depth is high but it's an unvalidated preprint with no community discussion provided.
📰 What's New
Researchers introduced KVBoost, a chunk-level key-value cache reuse system for HuggingFace-compatible decoder models that reuses shared content regardless of its position in the prompt. It uses a dual-hash scheme separating prefix hash from content hash to find exact and approximate cache matches. On Qwen/Qwen2.5-3B across 1,000 bug-localization samples, KVBoost cut time-to-first-token from 639.1 ms to 142.4 ms—a 4.49x reduction—and outperformed prefix caching by 16% while maintaining 99.2% accuracy versus 99.1%.
💡 Why It Matters： This reduces first-token latency for production LLM inference, particularly in workloads where repeated document snippets, code, or templates do not share a leading prefix. Because KVBoost works within a fixed memory budget and requires no model architecture changes, it can be deployed on existing RoPE-based HuggingFace models, potentially lowering per-request compute costs and improving responsiveness for retrieval-augmented generation and bug-localization services.
📊 Key Facts: 16% 99.2% 99.1%
Background
In transformer LLMs, the key-value (KV) cache stores attention keys and values computed from previous tokens so later tokens do not recompute them; prefill is the initial pass that processes the entire prompt before generating the first token, and time-to-first-token measures this latency. Prefix caching reuses KV entries only when many requests share the same leading prompt prefix, which fails when repeated material appears mid-prompt. RoPE (rotary position embedding) encodes token positions into attention and is widely used in models like Qwen2.5; KVBoost's design remains compatible with such models. Bug localization is the task of identifying probable faulty code locations from a bug report, used here as the evaluation workload.
Key Details
KVBoost's dual-hash keying separates positional identity (prefix hash) from content identity (content hash), enabling cache lookups independently of position. Two repair mechanisms address attention boundary errors: SelectiveRecompute re-encodes boundary regions, while CacheBlendRecompute runs a probe pass to detect high-deviation tokens and recomputes them. The system also applies asymmetric KV quantization to int8/int4, adaptively splits chunk boundaries, and uses importance-weighted eviction under a fixed memory budget.

CompPO Algorithm Introduces Architecture-Aware Credit Transport for LLM RL

rss ArXiv cs.AI · 2026-08-25 · ⌛ 5 min read
Reason：Novel framework for credit assignment in LLM reinforcement learning, addressing a key technical challenge with potential value to researchers, but as an arXiv preprint lacking community validation or demonstrated impact, it falls under important progress rather than breakthrough.
📰 What's New
Researchers introduced computation-conditioned credit transport (CCT) and the CompPO algorithm for architecture-aware credit assignment in large language model reinforcement learning. CompPO maps native attention concentration to a bounded per-token retention gate used in both a one-step bootstrap and a path-dependent generalized-advantage trace (Comp-GAE). Across five Qwen3-4B seeds, CompPO reached 61.4% final held-out accuracy (95% CI [60.8, 62.0]) versus 53.8% [52.9, 54.7] for tuned GRPO. In frozen evaluation, CompPO improved greedy pass@1 macro accuracy by 4.3 points on Qwen3-4B and 3.9 points on Llama-3.1-8B-Instruct over GRPO.
💡 Why It Matters： Credit assignment in LLM RL currently relies on architecture-agnostic operators such as fixed-discount GAE or group-relative GRPO, which ignore a Transformer policy's internal computation. CompPO's architecture-aware transport could give alignment researchers a drop-in modification that improves held-out accuracy and training stability without changing the task reward or clipped PPO objective. The reported 10/12 stable PPO-grid runs versus 3/12 for the baseline suggests the method may reduce hyperparameter sensitivity for practitioners tuning Qwen3-class models.
📊 Key Facts: 61.4% 95% 53.8%
Background
In LLM reinforcement learning, credit assignment decides which tokens in a generated response contributed to a task outcome. Generalized Advantage Estimation (GAE) applies a fixed geometric discount along token time, while group-relative methods like GRPO broadcast a summary statistic across an entire response. These transport operators are architecture-agnostic and ignore how the Transformer's attention concentrates on different tokens. Computation-conditioned credit transport (CCT) instead uses that internal attention concentration to shape how value flows back through the trajectory.
Key Details
CompPO uses a detached statistic of the behavior policy's internal computation to parameterize the causal kernel that transports downstream value through a rollout. A transport-aligned critic (TAC) reuses the actor's hidden states and routing information without a second same-scale Transformer. Ablations show Comp-GAE with a standard critic reaches 55.2% and TAC with a fixed gate reaches 56.4%, while the full model's interaction effect adds +2.4 [1.9, 2.9] percentage points.

SAEM: Stage-Aware Expert Management for Memory-Efficient MoE CoT Inference

rss ArXiv cs.AI · 2026-08-25 · ⌛ 5 min read
Reason：Novel runtime optimization for MoE inference during chain-of-thought reasoning, addressing memory and latency bottlenecks; technically deep and relevant for AI practitioners, though no discussion or engagement signals available.
📰 What's New
Researchers propose SAEM, a stage-aware MoE inference runtime that detects reasoning stage boundaries and exploits coherent expert activation patterns across consecutive stages. It combines stage-aware caching, expert-aligned token repacking, and in-situ CPU execution to reduce GPU-CPU data transfers and kernel fragmentation. On mathematical and scientific reasoning workloads under constrained GPU memory, SAEM averages 1.33x throughput over the strongest state-of-the-art caching and offloading baselines, rising to 1.54x when calibration data matches the workload.
💡 Why It Matters： For practitioners serving MoE LLMs with chain-of-thought decoding, SAEM addresses the key bottleneck where full expert weights exceed GPU memory, forcing expensive GPU-CPU transfers. The 1.33–1.54x throughput gain under constrained memory can lower per-query inference cost and latency for mathematical and scientific reasoning workloads. It demonstrates that exploiting stage-level locality, rather than uniform token handling, is a viable direction for memory-efficient MoE serving.
📊 Key Facts: 1.33 1.54
Background
Mixture-of-Experts (MoE) models scale parameter count by activating only a sparse subset of expert networks per token, but total expert weights can be too large for a single GPU's memory. Chain-of-thought (CoT) prompting makes LLMs generate intermediate reasoning steps before a final answer, which improves accuracy but increases the number of sequential decoding steps. During CoT decoding, consecutive tokens often belong to the same reasoning stage, creating predictable expert activation patterns that can be exploited to keep relevant experts near the GPU and reduce transfers.
Key Details
SAEM combines three mechanisms: stage-aware caching that retains expert weights for predicted active experts per reasoning stage, expert-aligned token repacking that groups tokens with similar expert preferences to reduce kernel fragmentation, and in-situ CPU execution for layers whose experts are not GPU-resident. The runtime detects reasoning stage boundaries rather than treating all tokens uniformly, exploiting coherent expert activation patterns across consecutive stages. The evaluation compared against strongest state-of-the-art caching and offloading baselines under constrained GPU memory, reporting average throughput improvement of 1.33x and up to 1.54x when calibration data matches the workload.

Across multiple model families and capability levels, most large language models controlled the direction and magnitude of residual stream activations with some degree of temporal resolution, though performance varied considerably. In simple tasks, this control evaded activation-based monitoring methods—including linear probes, natural language autoencoders, activation oracles, and the Jacobian lens—albeit imperfectly. 💡 Why It Matters： As models become more capable and evaluation-aware, latent-space monitoring is expected to complement behavioral evaluations, but controllable activations could extend deception into the latent space itself. Background
The residual stream is the main vector pathway through which information flows between layers in transformer models, and many interpretability methods analyze residual stream activations to infer internal states. Latent-space monitoring refers to inspecting internal activations rather than behavioral outputs to detect lying, scheming, or other undesirable tendencies. Linear probes are classifiers trained on activations; natural-language autoencoders and the Jacobian lens attempt to describe or interpret activations through language descriptions and gradient analysis, respectively.
Key Details
The benchmark measures the ability to steer the direction and magnitude of residual stream activations via natural-language prompts, including a temporal resolution dimension. Evaluated monitoring methods include linear probes, natural language autoencoders, activation oracles, and the Jacobian lens. Scroll Manages Long-Horizon Agent Context as Executable Python Environment

📰 What's New
Scroll treats each agent session as an executable Session Environment backed by an append-only Event Log and a sandboxed persistent Python kernel. The kernel maintains a typed namespace across model calls, binding tool outputs, retrieved history, and derived state to variables instead of serializing them into every prompt. Model-written code searches, materializes, and transforms session state through exec, and only explicitly printed projections enter the next working view. With Qwen3.8-Max, Scroll scores 94.8% on LongMemEval_S, 73.1% on BEAM_10M (5.1 points above the best published memory system), and 86.7% on LOCA_256K (37.4 points above the best published long-horizon agent).
💡 Why It Matters： By making context management a programming task, Scroll lets LLM agents inherit improving code-generation abilities and avoids irreversible compression or extraction before future needs are known. The append-only event log preserves lossless history, allowing long-horizon deployments to recover evicted regions precisely. This may reduce memory errors and maintenance cost in agentic workflows that span many steps or large document sets.
📊 Key Facts: 94.8% 73.1% 86.7%
Background
Long-horizon agents often accumulate history far beyond a single model context window, so prior systems compress or extract fixed memory representations early. Scroll instead retains an append-only log with exact addresses and uses model-written Python code to decide what to materialize. The eviction index lets the agent navigate directly to evicted regions rather than searching the full log.
Key Details
When the working view nears its budget, stale spans are evicted but recoverable through an eviction index that stores compact landmarks linked to exact Event Log addresses. The sandboxed Python kernel keeps a typed namespace and uses exec for search, materialization, and transformation. Only explicitly printed projections enter the model's next call, separating stored state from prompt context.
