📰 发生了什么
研究人员提出测试时记忆进化（TTME），一种即插即用的测试时适应方法，通过将经验蒸馏到外部记忆来指导后续发现，而不更新模型权重。在相同发现框架下对五项数学发现任务的评估中，TTME超越了测试时训练（TTT），同时将FLOPs计算成本降低82.8%至84.6%，运行时间降低47.7%至58.4%。该方法仅替换测试时适应部分，其余框架保持一致。
💡 为什么重要： 对于在科学发现中扩展测试时适应的大模型研究者和实践者，TTME提供了与TTT相当或更优的性能，同时大幅降低计算开销。这可能降低使用开放权重LLM进行持续发现的算力门槛，使更多团队能在有限预算下部署测试时适应。计算效率的提升也有助于减少大规模发现任务的能耗。
📊 关键数据: 82.8% 84.6% 47.7%
背景知识
测试时训练（TTT）指模型在推理或发现过程中继续更新自身权重以适应新任务，通常带来显著计算开销。测试时记忆进化（TTME）不改变权重，而是维护一个外部记忆来积累经验。科学发现任务常需要模型反复探索和修正假设，对适应方法的效率和性能要求较高。
关键细节
TTME通过持续更新外部记忆来蒸馏发现经验，模型权重保持不变，这与TTT在线更新权重的机制形成对比。实验在相同发现框架下进行，仅替换测试时适应方法，并在五项数学任务上全面超越TTT。其即插即用设计允许在不改动现有发现流程的情况下替换适应方法。

HyScale 以 2.07 倍加速长上下文稀疏注意力训练

rss ArXiv cs.AI · 2026-10-27 · ⌛ 2 分钟阅读
评分依据：Presents a significant system optimization for long-context training of learned sparse attention, delivering 2.07x speedup on 1M-token sequences over Megatron-LM. This directly addresses a known training bottleneck, offering practical value for AI infrastructure and potentially influencing how large-scale models are trained.
📰 发生了什么
HyScale 引入 HyTopK 和 selection replay 两项技术，消除了长上下文训练中的评分表物化和重复选择操作。在 100 万 token 序列上，它将 GLM-5.1 的训练速度提升至 Megatron-LM 的 2.07 倍，测试环境为 512 块 H20 GPU。在 32 块 H800 GPU 上处理 100 万 token 时，它还将 DeepSeek-V4-Flash 的 CSA 层加速 2.01 倍，将 Qwen3.8-Flash-Next 的 QSA 层加速 1.57 倍。其核心观察是选择输出是一组索引而非激活值，因此可避免存储完整注意力分数并在重计算中复用前向选择结果。
💡 为什么重要： 自 DeepSeek-V3.2 以来，学习型稀疏注意力已在生产环境中广泛采用，但选择操作在百万 token 上下文下成为训练瓶颈；消除该瓶颈可降低前沿长上下文模型的训练成本和时间。运行 GLM-5.1 或 DeepSeek-V4-Flash 等模型的 AI 基础设施团队可以利用 HyScale 在现有 GPU 集群上处理 100 万 token 序列，而不必等待更大内存或更多加速器。
📊 关键数据: 5.1 2.07 2.01
背景知识
学习型稀疏注意力通过让每个查询只关注少量 k 个 token 来降低内存和计算开销，但选择这 k 个 token 仍需要为所有先前 token 打分，在长上下文中代价高昂。现有系统会为所有查询- token 对物化完整的评分表，并在梯度重计算阶段重复执行选择，导致冗余计算。HyScale 的核心洞察是选择输出的是索引而非激活值，因此可以不用保存评分表，并能在重计算中重放索引集合。
关键细节
HyTopK 在不物化完整评分表的情况下，实时计算每个查询的精确 top-k，将选择输出视为一组索引。Selection replay 在重计算中复用前向传播的选择结果，避免对每个先前 token 的重复评分。这些技术与端到端训练优化结合，可在 100 万 token 序列上运行。

📰 发生了什么
ALTO是一个面向GPT-OSS-20B（200亿参数MoE模型）的开源训练方案，结合了混合1D/2D块量化、随机Hadamard变换、随机舍入以及从TetraJet-v2简化的权重去振荡方法。在C4验证集、全局批量大小16的设置下，MXFP4 + RHT + SR + 去振荡在16,128步达到3.3350的验证损失，仅比BF16基线3.3283高0.007，将MXFP4未使用去振荡时3.3418的差距缩小约50%。按达到MLPerf质量目标（验证损失3.34）所需步数计算，去振荡将FP4相对BF16的收敛开销从+20.0%降至+5.0%。差分梯度估计、异常值裁剪和宏块缩放虽在算子级SNR上有所提升，但端到端结果为负面。

📊 关键数据: 50% +20.0% +5.0%
