Partial Routing Delegates Subtasks to Cheaper Models, Cuts Cost 19%

rss ArXiv cs.AI · 2026-11-26 · ⌛ 5 min read
Reason：Novel technique for partial routing in agentic workflows, achieving measurable performance gains and cost reduction; directly relevant for practitioners optimizing LLM usage. No community discussion available in the provided content.
📰 What's New
Researchers introduced partial routing, a trace-tuned delegation method that allows a frontier lead model to assign suitable subtasks to a cheaper worker model during execution without training either model. On held-out ViBench tasks, partial routing with δ=0.75 raised the lead model's score from 70.2 to 78.5 while reducing cost by 19%. On Terminal-Bench 4.0, the pass rate improved from 54% to 61% at similar cost. The method analyzes past runs of both models to identify recurring subtasks and measure each model's quality and cost on them, producing delegation guidance.
💡 Why It Matters： For organizations running agentic workflows at scale, partial routing offers a practical way to cut inference spending without sacrificing output quality, because it avoids the binary choice of using a frontier model for every subtask or a cheaper model for the whole task. Developers can adopt the method without retraining models, making it easy to integrate into existing LLM pipelines. Trace-based routing policies could become a standard optimization layer alongside prompt caching and quantization.
📊 Key Facts: 19% 54% 61%
Background
Traditional model routing sends an entire task to the most appropriate model based on estimated difficulty, but agentic tasks often mix easy and difficult subtasks. Partial routing instead decomposes a task into subtasks and lets a stronger 'lead' model delegate only easier subtasks to a weaker 'worker' model during execution. ViBench and Terminal-Bench are benchmarks used to evaluate agentic task performance. The approach requires no fine-tuning, only analysis of historical execution traces.
Key Details
The delegation guidance is built from both models' past runs, identifying recurring subtasks and measuring each model's quality and cost on them. A parameter δ controls how much is delegated; setting δ=0.75 raised ViBench score from 70.2 to 78.5 at 19% lower cost, and Terminal-Bench pass rate from 54% to 61% at similar cost. Giving the lead model only the subtask breakdown—without a worker model—also reduced cost on both benchmarks and raised the Terminal-Bench pass rate.

Context Scaling Proposed as Third AI Scaling Paradigm

rss ArXiv cs.AI · 2026-11-26 · ⌛ 5 min read
Reason：The paper introduces a novel conceptual framework (context scaling) that reframes AI system bottlenecks and could influence how practitioners think about scaling beyond model and inference. It is an academic contribution with no community discussion signals provided, so not yet validated as breakthrough.
📰 What's New
An arXiv preprint (arXiv:2611.33160v1) introduces 'context scaling' as a third AI scaling paradigm that complements pretraining and decision-time scaling. It formalizes a model as P_θ(d|c) within a system governed by three budgets: training B_θ, decision-time B_d, and context-infrastructure B_c. Context scaling specifically targets the system's capacity to acquire, represent, deliver, evaluate, and persist deployment state before a decision is made. The framework separates deployment state from model-visible context and identifies availability, fidelity, selection, and utilization failures.
💡 Why It Matters： The framework reframes deployed AI failures as context mismatches rather than weak inference, which could shift investment toward context infrastructure budgets B_c instead of only larger models or longer inference. Practitioners building LLM systems may need to instrument and evaluate context acquisition, fidelity, and persistence as first-class components. The proposed utility-cost curves for context interventions could influence how AI infrastructure is designed and governed, especially for persistent, adaptive systems.
Background
Pretraining scaling improves a model by spending more compute on training parameters; decision-time scaling searches or refines outputs at inference time using extra compute. Context scaling focuses on the external state a model needs to act correctly—user state, repository revisions, tool traces, sensor readings—and how that state is collected, represented, and delivered. Many production AI failures stem from incomplete or distorted context rather than the model's reasoning ability, so budgeting for context infrastructure is a distinct axis of improvement.
Key Details
The paper defines effective-context value as a task- and intervention-dependent attribution and organizes mechanisms through a five-operation context lifecycle: acquisition, representation, delivery, evaluation, and persistence. It distinguishes deployment state from model-visible context and lists four failure classes: availability, fidelity, selection, and utilization. Evaluation is proposed through controlled budget interventions and utility-cost curves rather than static accuracy metrics.

Auditing Logical Reasoning Datasets for True Proof Depth and Certificates

rss ArXiv cs.AI · 2026-11-26 · ⌛ 5 min read
Reason：Technical research paper that audits logical reasoning datasets for actual proof depth, exposing inflations and proposing verifiable certificates. Valuable for AI evaluation and training, though no community discussion provided.
📰 What's New
An audit of eight procedurally generated logic datasets measured each problem's actual required proof depth under stated inference rules, computing forced steps, shortest proofs, minimal proof counts, and indispensable premises. The audit found forced depth in ProofWriter and Blocksworld, problems labeled depth 5 in FLDx2 requiring only about two specific rule applications, and ZebraLogic answers requiring no particular step. The researchers constructed problems whose every proof has the requested structure, using a catalog of shortcuts proved once per rule set, and exported certificates verified by an independent checker. Training experiments on Qwen3 models from 0.6B to 8B showed that mixtures of certified problem types, including model-checking problems not produced by forward generation, transfer better than FLDx2-style derivation data at equal size.
💡 Why It Matters： This audit reveals systematic overstatement of difficulty labels in existing logical reasoning benchmarks, which can mislead model evaluation and training data selection. Dataset designers gain a verifiable difficulty standard through proof certificates, enabling more trustworthy reasoning benchmarks. For model trainers, mixing certified problem types improves transfer performance in small models (0.6B–8B), reducing reliance on large-scale generated derivation data.
Background
Procedurally generated logic problems are widely used to train and evaluate reasoning in language models. Their difficulty is typically set by planting a proof: sampling a proof of desired depth and stating its premises as the problem. However, a planted proof is only one possible proof; a problem can also have shorter proofs or several unrelated ones, making the stated depth overstate what solving requires. Proof depth refers to the minimum number of derivation steps needed under a given set of inference rules. Certificates verified by an independent checker allow third parties to validate difficulty claims.
Key Details
The method computes, for each problem, the steps every proof must take, the shortest proof length, the number of minimal proofs, and the indispensable premises, then exports certificates that an independent checker verifies. To construct shortcut-free problems, the researchers prove a catalog of shortcuts once per rule set and use it to build problems whose every proof has the target structure, including model-checking problems that forward generation cannot produce.

Real-Time Reasoning Training Boosts AI Agent Rewards Up to 55%

rss ArXiv cs.AI · 2026-11-26 · ⌛ 4 min read
Reason：Presents novel real-time reasoning training techniques for AI agents, addressing a significant gap between synchronous training and real-time environments; arXiv preprint without peer review or community discussion, but technical novelty is high.
📰 What's New
Real-time reasoning training (RRT) has been introduced as a class of training techniques for AI agents operating in environments that change independently of the agent. The approach uses three standard techniques: real-time data, decoupling acting and observing, and curriculum learning in time. In Frogger and Snake, RRT outperformed the strongest non-RRT baseline by an average of 33% reward on in-distribution tasks and 55% on out-of-distribution tasks. This demonstrates that agents can learn to balance reasoning and responsiveness under real-time constraints.
💡 Why It Matters： The work addresses a gap between synchronous training environments and real-world settings where delays carry costs. Agents trained with RRT can decide when to act immediately versus think longer, which could improve performance in robotics, autonomous driving, and high-frequency trading systems. The 55% out-of-distribution gain suggests better generalization to unseen time pressures.
📊 Key Facts: 33% 55%
Background
Most modern AI agents are trained in synchronous environments where the world waits for the agent to choose an action before changing state. Real-time environments, such as video games or physical robots, evolve continuously regardless of the agent's decisions. Existing approaches impose a fixed thinking-to-acting ratio, but RRT instead lets agents learn when longer reasoning is worth the delay. Training techniques like curriculum learning gradually expose agents to harder time constraints.
Key Details
RRT comprises three techniques: training on real-time data instead of turn-based data, decoupling action and observation so the agent can act while the world evolves, and curriculum learning that gradually increases time pressure. These techniques were evaluated in Frogger and Snake, with reward improvements of 33% in-distribution and 55% out-of-distribution compared with the strongest non-RRT baseline.
