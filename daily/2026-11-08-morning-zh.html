Claude Code “Don’t Ask Again” 致 1,122 个公开 GitHub 文件泄露密码

hackernews shmulc · 2026-11-07 · ⌛ 2 分钟阅读
评分依据：High-value security finding that affects AI developers using Claude Code; reveals over 1,100 public GitHub files with exposed secrets due to misconfigured local settings, with an official Anthropic response and 294 comments showing substantive community discussion and risk mitigation strategies.
📰 发生了什么
安全研究人员在 1,122 个公开 GitHub 文件中发现 Claude Code 的本地设置文件 .claude/settings.local.json 因“Don’t Ask Again”配置而暴露密码。这些文件是开发人员手动创建并提交到公开仓库的，而 Claude Code 通常会在创建该文件时自动将其加入 .gitignore。泄露的配置包含直接嵌入命令文本中的 API 密钥和密码等敏感信息。Anthropic 的 Claude Code 团队成员 Boris 确认了该问题，表示团队正在研究预防措施，但强调该文件本应留在本地。
💡 为什么重要： 使用 Claude Code 并发布公开仓库的开发人员，如果提交了 .claude/settings.local.json，就可能泄露 API 密钥、数据库凭据或云服务访问权限，导致账户被入侵。该发现暴露出 AI 编码代理在“不再询问”等便捷功能下将敏感命令字符串存储在本地的风险，而许多开发者并未意识到需要排除此文件。Anthropic 的回应表明未来可能添加防护，但当前责任仍在开发者。
📊 关键数据: 1,122
背景知识
Claude Code 是 Anthropic 开发的 AI 编码助手，允许用户通过命令行与 AI 交互。“Don’t Ask Again” 让用户批准某条命令后，Claude Code 后续执行相同命令时不再提示，但该命令连同其中的秘密会被保存在 .claude/settings.local.json 中。该文件本应只存在于本地开发环境；若被提交到公开 GitHub 仓库，任何人均可访问。公开仓库中的此类文件可直接搜索到。
关键细节
Claude Code 历史上未执行秘密清理，嵌入已批准命令中的秘密以明文形式保留在设置文件中。受影响的文件位于公开 GitHub 仓库中，表明开发者手动创建并提交了 .claude/settings.local.json，而不是依赖自动化 .gitignore。该文件通常包含权限和命令批准配置，“Don’t Ask Again”会存储包括参数在内的完整命令。

MaxxBench 变异89个 DeepSWE 任务揭示基准脆弱性

hackernews antiuniverse · 2026-11-07 · ⌛ 2 分钟阅读
评分依据：High value for AI practitioners and researchers: it exposes weaknesses in DeepSWE benchmark through parameter variation, includes technical depth and insightful community discussion (86 comments) about benchmark validity, bugs, and model size collapse, with practical implications for model evaluation.
📰 发生了什么
Unlap AI 推出的 MaxxBench 对 89 个 DeepSWE 编码任务进行变异，通过改变指令或起始代码（例如要求小写文件名或 UTC 时间戳）来测试模型泛化能力。变异后补丁中位增量仅为 17 行（3.5%）。结果显示，小型 '-flash' 模型和 OpenAI Luna 分数崩塌最严重，GPT-5.6-Sol 明显优于 GPT-5.6-Luna；DeepSeek 在启用高参数模式时 API 行为几乎归零。
💡 为什么重要： 这些结果表明，DeepSWE 等流行基准分数可能无法泛化到真实世界的任务变化，削弱了 AI 编码助手评估的可靠性。实验室可能在 RL 环境中过度拟合基准约定，企业若依赖排行榜排名，可能选用在轻微变化任务上失败率大增的模型。小模型崩塌更严重的现象，进一步暴露了行业模型选择中的鲁棒性差距。
📊 关键数据: 3.5% 5.6
背景知识
DeepSWE 是一个流行的软件工程基准，用真实 GitHub issue 和补丁评估大语言模型的编码能力。基准一旦流行，任务可能进入训练数据、影响检查点选择并引导提示词微调，导致分数虚高。MaxxBench 通过系统性地变异任务规格，检验分数反映的是真实能力还是对基准惯例的过度拟合。
关键细节
该测试通过改变任务说明与起始代码生成变异样本，同时将补丁中位增量控制在 17 行（3.5%），避免简单增加难度。测试还发现 DeepSeek 的 API 在启用 high/max 模式时得分几乎为零，显示采样参数对结果影响巨大。GLM-5.3 与 GLM-5.3-flash 属于不同谱系，因此不遵循小模型崩塌的规律。
