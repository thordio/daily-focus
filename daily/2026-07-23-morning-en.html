SysAdmin simulates realistic sysadmin scenarios to probe these tendencies, offering a pre-deployment diagnostic for alignment and safety.

ToolDNS: Scalable AI Tool Discovery via DNS

rss ArXiv cs.AI · 2026-07-23 · ⌛ 4 min read
Reason：Proposes a novel framework leveraging DNS for scalable, decentralized AI tool discovery, with a large benchmark; potentially significant for autonomous agents.
📰 What's New
Researchers propose ToolDNS, a framework that uses the Domain Name System (DNS) for AI tool discovery, reducing search complexity from O(N) to O(log N). It was evaluated on a heterogeneous benchmark of 33,688 real-world tools spanning MCP, A2A, RESTful, and Skill protocols. ToolDNS slashes per-query search space by 95.26% while matching state-of-the-art retrieval accuracy. Its UDP-native design reduces discovery latency by orders of magnitude compared to HTTP-based registries.
💡 Why It Matters： As autonomous AI agents proliferate, efficient tool discovery at scale becomes critical. ToolDNS leverages existing DNS infrastructure, enabling scalable discovery without new middleware and lowering barriers for distributed AI systems. Its decentralized governance and semantic pruning can make tool management more flexible and trust models more transparent, potentially influencing future agent architectures.
📊 Key Facts: 95.26% 33,688
Background
DNS is the foundational internet service that resolves domain names to IP addresses using a hierarchical, distributed architecture. ToolDNS encodes AI tools' functional intents and trust information into hierarchical domain-like names, enabling agent discovery similar to DNS resolution. EDNS0 is a DNS protocol extension that allows additional options in requests and responses, which ToolDNS uses for intent payloads. Traditional tool discovery relies on centralized registries or semantic search with O(N) complexity that degrades as tools grow; ToolDNS adapts DNS tree resolution and semantic pruning to rapidly exclude irrelevant tools, achieving O(log N) lookup.
Key Details
Partially unfolded names allow iterative intent matching without full domain knowledge; EDNS0 intent payloads carry semantic information in DNS extension headers; logical subdomains group tools by organization or trust domain. The benchmark comprises 33,688 tools across four protocols. UDP-native design eliminates TCP connection overhead, achieving microsecond-level resolution.

📰 What's New
Researchers introduced MILP-Evo, an LLM-guided framework that automatically designs cut selector and branching rule logic for MILP solvers. Candidate programs are iteratively generated, loaded into SCIP via PySCIPOpt, and evaluated by direct execution on MILP instances. The evolution process uses performance-based selection, targeted repair, diagnostic reflection, and diversity-aware population maintenance. Across four benchmark families, MILP-Evo discovered competitive domain-specialized policies.
💡 Why It Matters： By producing explicit, white-box solver components, MILP-Evo enables easier inspection, modification, and deployment compared to black-box learned policies. This could accelerate solver customization for industries like supply chain and manufacturing, where MILP is heavily used, reducing the need for manual algorithm design.
Background
Mixed-integer linear programming (MILP) solvers are fundamental tools in operations research, solving optimization problems with both continuous and integer variables. Key solver components like branching rules and cut selectors significantly impact performance. Traditionally, these are hand-crafted by experts or tuned via manual experimentation. Recent ML methods learn policies as neural networks, but they are often opaque and hard to integrate into existing solver codebases.
Key Details
MILP-Evo operates within SCIP, using PySCIPOpt to load and execute candidate programs. The framework simultaneously designs a cutting plane selector and a variable branching rule, incorporating targeted repair and diagnostic reflection based on solver performance feedback. A diversity-aware population maintenance mechanism is used to prevent premature convergence.

It integrates a lightweight latency estimator that simulates autoregressive token batch processing in the serving framework to predict each query's time-to-first-token (TTFT). The router jointly optimizes latency, accuracy, and cost when assigning queries to model instances. Experimental results show up to a 40% improvement in accuracy–cost utility while maintaining latencies on par with standard load-balancing approaches.

📊 Key Facts: 40%
Background
LLM query routing directs each incoming query to the most suitable model instance among a pool, balancing response quality and cost. Time-to-first-token (TTFT) is the delay before the model starts generating a response. Dynamic workloads involve fluctuating request patterns, making static routing suboptimal. Existing routers neglect latency, potentially causing high TTFT and poor user experience.
Key Details
The latency estimator models the serving framework's scheduling and batching policies, accounting for prompt length, current prefill and decode workloads. The router performs joint optimization over latency, accuracy, and cost, rather than treating them independently. The 40% utility gain was achieved under the same latency constraints as standard load balancing.

S2T-RLHF Uses Sentence-Level Rewards to Stabilize RLHF Training

rss ArXiv cs.AI · 2026-07-23 · ⌛ 4 min read
Reason：Proposes a granularity-aware principle for hierarchical credit assignment to improve RLHF training stability, addressing a known issue with practical implications for LLM alignment. No discussion comments provided.
📰 What's New
A new method called S2T-RLHF introduces hierarchical credit assignment for preference-based RLHF. It decomposes sequence-level rewards into sentence-level allocations first, then applies bounded token-level refinement within each sentence. Unlike prior approaches, it does not require reward-model retraining or token-level supervision. Experiments on multiple datasets show improved training stability and robustness while maintaining competitive preference alignment.
💡 Why It Matters： Standard RLHF often suffers from unstable training due to ambiguous credit assignment from sequence-level rewards. S2T-RLHF's granularity-aware design mitigates noise amplification from overly fine-grained reward refinement, a known issue in LLM alignment. This could make RLHF more reliable for training large language models to follow human preferences.
Background
Reinforcement Learning from Human Feedback (RLHF) aligns LLMs using preference-based reward models, typically providing only a single scalar reward per response. This makes token-level credit assignment inherently ambiguous, leading to training instability. Recent work attempts to create denser token-level rewards, but overly fine-grained refinement can amplify noise in preference signals.
Key Details
The framework uses sentences as an intermediate granularity to balance semantic coherence and robustness. It first computes sentence-level rewards from the sequence-level preference signal, then refines token-level rewards within each sentence with bounded constraints. This avoids the instability of directly assigning dense token-level rewards from noisy preference data.

Epistemic harms relate to truth and authenticity, while dignity harms involve personal autonomy. Current deepfake research focuses on the former, such as political disinformation and fraud, even though the predominant real-world misuse is sexualized imagery.
Key Details
The study conducted a quantitative analysis of 39 influential defense papers, finding all interventions are viewer-centric authenticity detections, none addressing victim perspectives. It emphasizes that even synthetic imagery causes 'dignity harms,' and current detection tools can increase perceived authenticity, worsening psychological trauma.
